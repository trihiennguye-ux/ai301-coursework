I wrote the landing page design for CampusOS, an open-source platform for running campus operations, and the maintainers merged it. It's a 402-line plan that tells developers which sections the page needs, how it should look on phones and desktops, and which parts of the existing design to reuse.

The page had already been built before anyone wrote a design down, so I started by checking what was really there. Three sections the project wanted were missing, and the page showed numbers like "99.9% uptime" that nothing backed up. My plan replaces those numbers with facts that are true about the project.

The maintainers hadn't answered my questions yet, so I made the calls myself and explained each one in writing. When they reviewed my pull request, they said my choice of format was "100% the right call" and merged it the same day. The work to build the page from my design will be tracked as a separate task.

What I learned: checking what exists before designing anything matters. My first message called the page a placeholder, and reading the code proved me wrong. I'd rather catch that myself than have a reviewer catch it.
